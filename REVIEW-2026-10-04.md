| Area | Defect and changed behavior | Evidence files |
| --- | --- | --- |

## Remaining release blockers and exact next steps

| Priority | Confirmed gap / verification limitation | Required solution |
| --- | --- | --- |
| P0 | Inbound case/AI work is launched after storage with an unawaited promise; its ordering queue lives in process memory. A restart can lose work, and a stored duplicate can skip an unfinished attempt. Deterministic IDs improve deduplication but do not guarantee exactly-once processing across replicas. | Persist a webhook job atomically with the inbound record. Add leased workers, retry state and deterministic reply/outbox IDs. Test crashes after each write and simultaneous webhook delivery across two workers. |
| P0 | Outbound send and local persistence are separate operations. A timeout can mean Meta accepted a send without the app knowing; a receipt can arrive before its local record exists. Unknown receipts currently have no replay store. | Use a durable outbound outbox and persist receipt events for reconciliation. Test provider timeout after acceptance, restart before message-ID save and receipt-before-record races. Do not claim guaranteed delivery until these pass. |
| P0 | Account linking now demands verification, but historical phone matches and legacy counselor IDs need a staging migration/identity audit. | Inventory affected records, verify numbers, resolve aliases and merge only confirmed identities. Do not automatically merge histories using a bare phone value. |
| P0 | True role access and end-to-end data-policy compatibility remain untested against PostgreSQL. Stronger permissions can expose old screens relying on unauthorized generic writes. | Test distinct student/admin/telecaller/counselor accounts, cross-student and cross-branch denial, disabled accounts, reset delivery, real uploads, reuploads and expired sessions. Verify deployed commit. |
| P1 | Incoming WhatsApp media is represented by text such as [Document]; it is not downloaded and attached to a document request in the application. | Store media IDs/type, authenticate Meta media download, validate size/type, scan files, store under verified student ownership, and link the exact pending request. Require human confirmation when document type is unclear. |
| P1 | Automatic pending-document/application/overdue WhatsApp reminders and approved templates outside the reply window are not fully implemented. | Add event rules, opt-in/consent, approved templates, reminder dedupe, preferences and delivery tracking. Test inside/outside the window and declined reminders. |
| P1 | My Preferences with `preference_rank` and a separate counselor/application handoff model remain absent. Apply still starts the old form; `pending_counselor` remains an internal status. Wording fixes do not implement the requested workflow. | Add a separate ranked preference model, Admin intent/AI-summary view, explicit review queue, and truthful application state transitions. Migrate old states based on evidence, not labels. |
| P1 | Verified campus photos, country/course/city costs, scholarships and actionable country updates are not supplied by the existing catalogue. | Populate source/date/currency fields and verified image URLs; show unknown values until verified. Feed only updates affecting the student's destination/intake/next step. |
| P1 | AI staff copilot (internal summary, suggested responses and follow-up prompts) is not complete. | Keep suggestions internal, require staff approval and log edits; do not allow AI to take over human ownership. |
| P1 | Email reset, Gemini answers, assignment notices and document delivery exist as code paths but are not proven with current production credentials. | Run one new website lead and one WhatsApp-only lead through Admin allocation, telecaller conversion, counselor assignment and one document/application update. Observe delivery/read receipts on a real phone. |
| P2 | No load/restart/mobile visual test was run; the frontend has a large student chunk and several APIs load entire JSON tables. | Split student routes and heavy admin features, paginate indexed queries, measure memory/p95 response time, and test real mobile widths before sizing hosting. |
| P2 | Backups, crash alerts and recovery are not verified here. | Configure error aggregation, readiness checks, monitoring and backup restore drills; define deploy health checks and a tested rollback. |

## Cleanup decisions

No arbitrary source files were deleted. The confirmed duplicate unsigned webhook definitions were removed from `server/routes/core.mjs`. Keep `server/student/whatsapp.ts`: it is the active handler. Keep `server/lib/whatsappStore.mjs` until all non-webhook callers have been replaced and tested. Older student staff/chat components, seed data and fallback APIs are cleanup candidates only after a route/import and data migration audit. Do not remove configuration examples, migrations, uploads or tests just because they are unused in one screen.

## Suggested staging gate

1. Review and apply this branch to staging, using the uploaded baseline rather than overwriting a newer GitHub branch.
2. Configure staging database, email, Gemini, Meta phone-number ID/access token/app secret/verify token. Verify the business sender, not just its website contact link.
3. Prove login, record isolation, uploads and assignment using four distinct test roles.
4. Prove one inbound/outbound WhatsApp journey and record device delivery/read statuses.
5. Close the durable queue/outbox and document-media gaps above, then rerun crash/retry tests.
6. Complete the preference/application product workflow, verified content and mobile review before approving release.
